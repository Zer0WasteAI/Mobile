# 🏗️ ZER0 WASTE AI - FRONTEND ARCHITECTURE OVERVIEW\n\n## 📋 **PROJECT INFORMATION**\n\n**PROJECT NAME:** ZER0 Waste AI  \n**FRAMEWORK:** Flutter 3.x  \n**STATE MANAGEMENT:** Riverpod  \n**ARCHITECTURE:** Clean Architecture + Feature-Based Structure  \n**NAVIGATION:** GoRouter  \n**BACKEND:** MCP Backend REST API  \n**DATABASE:** Firebase + Local Storage (Hive + SharedPreferences)  \n\n---\n\n## 🎯 **CORE CONCEPT**\n\nZER0 Waste AI is a **food waste reduction app** that uses **AI-powered food recognition** to help users:\n- **Scan and identify** ingredients and prepared foods\n- **Manage inventory** with expiration tracking\n- **Generate smart recipes** based on available ingredients\n- **Track environmental impact** of food waste reduction\n- **Plan meals** to optimize ingredient usage\n\n---\n\n## 🏛️ **ARCHITECTURE PATTERNS**\n\n### **1. CLEAN ARCHITECTURE LAYERS**\n\n```\n📁 lib/\n├── 📁 core/                    # Shared infrastructure\n│   ├── 📁 services/            # API, Storage, Auth services\n│   ├── 📁 theme/               # UI theming system\n│   ├── 📁 navigation/          # GoRouter configuration\n│   ├── 📁 widgets/             # Reusable UI components\n│   └── 📁 utils/               # Helper utilities\n│\n├── 📁 features/                # Feature modules\n│   ├── 📁 auth/                # Authentication & user management\n│   ├── 📁 home/                # Dashboard & overview\n│   ├── 📁 inventory/           # Food inventory management\n│   ├── 📁 recipes/             # Recipe generation & management\n│   ├── 📁 recognition/         # AI food recognition\n│   ├── 📁 scan/                # Camera scanning interface\n│   ├── 📁 impact/              # Environmental impact tracking\n│   ├── 📁 planner/             # Meal planning\n│   ├── 📁 profile/             # User preferences & settings\n│   └── 📁 navigation/          # Bottom navigation\n│\n└── 📁 main.dart                # App entry point\n```\n\n### **2. FEATURE MODULE STRUCTURE**\n\nEach feature follows **Clean Architecture** principles:\n\n```\n📁 feature_name/\n├── 📁 application/             # Application layer\n│   ├── 📁 providers/           # Riverpod state providers\n│   └── 📁 states/              # State models (Freezed)\n│\n├── 📁 data/                    # Data layer\n│   ├── 📁 datasources/         # External data sources\n│   ├── 📁 models/              # Data models (JSON serialization)\n│   └── 📁 repositories/        # Repository implementations\n│\n├── 📁 domain/                  # Domain layer\n│   ├── 📁 entities/            # Business entities\n│   ├── 📁 models/              # Domain models\n│   ├── 📁 repositories/        # Repository contracts\n│   └── 📁 usecases/            # Business logic\n│\n└── 📁 presentation/            # Presentation layer\n    ├── 📁 screens/             # Full-screen widgets\n    ├── 📁 widgets/             # Feature-specific widgets\n    ├── 📁 providers/           # UI state providers\n    └── 📁 viewmodels/          # Screen controllers\n```\n\n---\n\n## 🔄 **STATE MANAGEMENT - RIVERPOD**\n\n### **PROVIDER TYPES USED:**\n\n1. **StateProvider** - Simple state values\n2. **StateNotifierProvider** - Complex state with business logic\n3. **FutureProvider** - Async data loading\n4. **StreamProvider** - Real-time data streams\n5. **Provider** - Dependency injection\n\n### **KEY PROVIDERS:**\n\n```dart\n// Authentication\nfinal authStateProvider = StreamProvider<User?>\nfinal userProfileProvider = StateNotifierProvider<UserProfileNotifier, UserProfileState>\n\n// Navigation\nfinal currentNavigationProvider = StateProvider<String>\n\n// Inventory\nfinal inventoryProvider = StateNotifierProvider<InventoryNotifier, InventoryState>\n\n// Recipes\nfinal aiRecipeProvider = StateNotifierProvider<AIRecipeNotifier, RecipeState>\n\n// Recognition\nfinal recognitionProvider = StateNotifierProvider<RecognitionNotifier, RecognitionState>\n```\n\n---\n\n## 🧭 **NAVIGATION SYSTEM**\n\n### **GoRouter Configuration:**\n\n1. **Root Routes** - Full-screen navigation\n2. **Shell Routes** - Bottom navigation wrapper\n3. **Nested Routes** - Feature-specific flows\n\n### **NAVIGATION STRUCTURE:**\n\n```\n🏠 Root Navigator\n├── /splash                     # App initialization\n├── /onboarding                 # First-time user flow\n├── /login                      # Authentication\n├── /register                   # User registration\n├── /allergy-selector           # Preference setup\n├── /cooking-level-selector     # Skill level setup\n├── /preferred-food-type        # Food preferences\n├── /special-diet-selector      # Dietary restrictions\n│\n└── 📱 Shell Navigator (Bottom Bar)\n    ├── /home                   # Dashboard\n    ├── /inventory              # Food management\n    ├── /recipes                # Recipe exploration\n    └── /profile                # User settings\n```\n\n### **NAVIGATION GUARDS:**\n\n- **Authentication Guard** - Redirects unauthenticated users\n- **Onboarding Guard** - Ensures preference completion\n- **Deep Link Handling** - Preserves navigation state\n\n---\n\n## 🎨 **UI/UX SYSTEM**\n\n### **THEME ARCHITECTURE:**\n\n```dart\nclass AppTheme {\n  static ThemeData lightTheme\n  static ThemeData darkTheme\n  static ThemeData getTheme(ThemeMode, BuildContext)\n}\n```\n\n### **COLOR SYSTEM:**\n\n- **Primary Colors** - Green eco-friendly palette\n- **Secondary Colors** - Accent colors for actions\n- **Semantic Colors** - Success, warning, error states\n- **Neutral Colors** - Text, backgrounds, borders\n\n### **COMPONENT LIBRARY:**\n\n```\n📁 core/presentation/widgets/\n├── smooth_button.dart          # Custom button component\n├── smooth_card.dart            # Card with rounded corners\n├── loading_snackbar.dart       # Loading feedback\n├── app_dialog.dart             # Modal dialogs\n├── selectable_item_chip.dart   # Selection chips\n└── unfocus_detector.dart       # Keyboard management\n```\n\n---\n\n## 🔌 **EXTERNAL INTEGRATIONS**\n\n### **BACKEND API:**\n- **Base URL** - Environment-based configuration\n- **Authentication** - JWT with automatic refresh\n- **Error Handling** - Centralized error management\n- **Retry Logic** - Automatic request retries\n\n### **FIREBASE SERVICES:**\n- **Authentication** - User login/registration\n- **Firestore** - User preferences storage\n- **Storage** - Image upload and management\n\n### **LOCAL STORAGE:**\n- **Hive** - Structured local data\n- **SharedPreferences** - Simple key-value storage\n- **Secure Storage** - JWT token storage\n\n---\n\n## 📱 **MAIN FEATURES**\n\n### **1.
